# 按号抓取（公众号「列表模式」）PRD

> 版本 v0.3 ｜ 状态：**已实现，等一次解锁后的实盘验收**（2026-11-08） ｜ 日期：2026-11-08
>
> 用户原话（第一轮）：
> 「我要抓取某个公众号的最新的文章列表，这个你需要切换到列表模式。而且在列表模式，
> 最新的是在底部，所以需要从下往上翻，还有可能一天发了多篇，我只需要取第一篇。」
>
> 用户拍板（第二轮，四选一）：
> ① 定位方式 = **本地 OCR 自动找**；② 范围 = **一次一个号**；
> ③ 篇数 = **默认 20 篇，从下往上取**；④ 产出 = **单独出一份精选号简报**。

## 1. 要达到什么

新增一条与「信息流 20 篇」并列的入口：**指定一个公众号 → 从最新（底部）往上，
逐次推送取头条，凑够 20 篇**。同一次推送里的其余几条不要（这就是「一天发了多篇
只取第一篇」的落点：一次推送 = 一组卡片，组内只取带封面的头条）。

产出单独成一份简报，不和信息流那份混。

## 2. 现状盘点

### 能直接复用的

| 能力 | 位置 | 复用方式 |
| :--- | :--- | :--- |
| 点开文章 →「…」→ 复制链接 → 关窗 | `grab._open_and_copy` | 原样调用（含标题带守卫、文章窗口确认、删除页跳过、Cmd+W 保护） |
| 标题行像素识别 / 跨屏指纹 | `feed_vision.find_card_titles` / `fps_close` | 认「组内分组」、判「滚到顶」、防重复点 |
| 切前台 / 挡窗检查 / 几何自检 | `nav.ensure_front` / `grab.preflight` | 每次点击前照旧 |
| 滚轮 | `gui.scroll` | 滚右栏 |
| 链接文件进候选池 | `main.cmd_scan --urls-file` | 新入口只产出 urls 文件 |

### 缺的（这次要新写）

1. **切模式**：现有代码把「号列表形态」当**错误**（`nav.looks_like_account_list`，
   2026-11-07 事故后加的护栏）。新需求要主动进这个形态，跑完还得能切回卡片流。
2. **按名字找号**：现有全流程零 OCR，只认几何特征，**无法认字**。这是唯一真正的
   架构增量，已拍板走本地 OCR。
3. **认「一次推送」的边界**：一次推送 = 一个卡片容器里的 N 篇（头条带封面图 +
   若干纯文字条）。要只取头条，就得先认容器边界与「组内第一条」。
4. **单号单报的命名空间**：见 §6，现有所有产物按日期命名，两份简报同日会互相覆盖。

## 3. 目标流程（每步都有成功判据，判不过就停）

```
S0  preflight（平台 / 微信在跑 / 未锁屏 / 几何自检）            —— 复用
S1  切列表模式：点页面右上角切换按钮 → 复验「号列表形态」
S2  左栏按名字定位目标号（OCR，规范化后精确匹配）→ 点名字行
S3  复验右栏顶部标题 == 目标号名                                ← 防点错行
S4  滚到底：连续两次滚动后底部组指纹不变 = 已到最新
S5  循环取篇（直到 20 篇，或滚到最顶/连续无新增）：
      a. OCR 找右栏最下方一组（一次推送）
      b. 取该组第一条（带封面的头条）→ 记录标题 + 指纹
      c. grab._open_and_copy 拿链接 → 追加进 urls
      d. 向上滚一屏，回到 a
S6  收尾：切回卡片模式（否则下次跑信息流会误报「号列表形态」）
```

**为什么 S4 用「滚到底 + 滚不动了」判定**：你说最新在底部，但右栏打开时停在顶部
还是底部，不同账号不一定一致。用「滚到底 + 连续无变化」判到底，两种情况都成立，
代价是多 2~3 次滚动。

**为什么 S5 用指纹去重**：向上滚动时上一屏的组会重复出现（滚动幅度 < 一屏），
现有 `fps_close` 正好用于「这篇点过了，跳过」。

## 4. 已实测的事实

拿你那张列表模式截图跑了 macOS Vision OCR（`swiftc` 本机可用，和 `winpos` 的 swift
编译缓存是同一套机制，无第三方依赖、不联网、不用申请权限）：

| 事实 | 实测值 |
| :--- | :--- |
| 中文识别准确率 | 号名 / 标题几乎全对，置信度多为 **1.0**（「EarlETF」「猫笔刀」「复利先生」全中） |
| 左栏每行结构 | 号名一行 + 该号最新标题一行（相距约 44 图像 px）+ 右端星标；行距约 135 图像 px |
| 一屏可见号数 | 约 9~10 个 → **目标号常在屏幕外，必须能滚左栏 + 设上限** |
| 右栏结构 | 顶部号名；正文「时间分隔（昨天 08:31）→ 卡片组（头条带封面 + 3 条纯文字）」 |
| 组内第一条 | 「恒科也算亚太之光了」带封面大图，其后 3 条纯文字，同组同次推送 |
| 交叉校验点 | 左栏 EarlETF 显示「恒科也算亚太之光了」= 右栏该组第一条 → 左栏第二行就是该号最新一次推送的头条标题 |

> 以上是**截图像素空间**，上机必须先实测 1280x832 逻辑空间的四个数
> （切换按钮坐标、左栏右边界、行高、组间距），不照抄截图。

### 6.2 命名空间（「单独一份」的代价，必须先说清）

现在所有产物按**日期**命名，两份简报同日直接互相覆盖：

```
out/inbox-<日期>.json                  ← review/_latest_inbox 靠 glob 取最新
out/_plan/selected-<日期>.json
out/_plan/summary-request-<日期>.json  ← 人工放行信号
out/pending_summary.json
out/_batches/batch-N.{json,md}
```

方案：引入 **scope**（`feed` 默认 / `account-<号名>`），产物加后缀：

```
out/inbox-2026-11-08-EarlETF.json
out/_plan/selected-2026-11-08-EarlETF.json
out/_plan/summary-request-2026-11-08-EarlETF.json
out/pending_summary-EarlETF.json
out/_batches/EarlETF/batch-1.{json,md}
```

波及：`main.py`（各子命令加 `--scope`）、`selection.py`、`prompt.py`、`publish.py`
（标题「公众号简报·EarlETF 2026-11-08」）、`review.py`（`_latest_inbox` 与
`/review` 要按 scope 取，不能盲取最新）。**台账不动**：`seen` / `offered` / `runs` /
`published` 共用一份（同一篇文章不该因为换个入口就被总结两次）。

## 7. 失败与停轮（沿用现有铁律）

- 找不到号 / 右栏标题与目标号名不一致 / 到底判定不了 / 头条点不开文章
  → **停，退出码 3**，留现场截图，不猜、不盲点、不挪坐标重试。
- 左栏滚到上限仍没这个号 → 报「左栏滚了 N 屏没有 X」，不写任何台账。
- **头号高危项（必须先验证）**：文章在右栏点开是否仍是**独立浮动窗口**。
  若不是浮窗，现有 `Cmd+W` 会关掉微信主窗口（2026-11-07 已踩过一次）。
  所以开工第一步是**单击一次观察**，再决定关窗方式。
- 跑完停在列表模式会让下次信息流抓取误报 → S6 切回卡片模式，且 `to_feed`
  支持自动切回（双保险）。

### 10.2 与原设计的偏差（都是实测逼出来的）

1. **拿链接不用「…」菜单，改走「地球」**。标签页右端的「…」菜单在 mouseDown 弹出、
   mouseUp 命中第一项，**一点就把标签关掉**（试两次都一样）。改成点「地球」→
   文章在浏览器打开、微信自动关标签回列表页 → 浏览器 `Cmd+L` / `Cmd+C` / `pbpaste`。
   **全链路零 Cmd+W**，第 7 节那个「头号高危项」因此彻底消失。
2. **头条用 OCR 行定位，不用像素标题带**。右栏卡片有封面图和右侧缩略图，两者与标题
   在像素上粘成一条 155px 高的带子，按「标题带高 6~24」过滤会把头条整条丢掉，
   于是错取成组内第二条。OCR 行没有合并问题。
3. **左栏号名 = 组内最上面那行**，不是「字号最大那行」。实测「疯狂计划」h=17 比
   「猫笔刀」h=16 只大 1px，按字号挑会认错行。
4. **时间行正则尾部放宽 4 个非数字字符**。OCR 把分隔线读成「星期四 07:32|」，
   不放宽就漏掉整次推送。
5. **不点卡片、不点浮窗**：文章在列表模式下就是主窗口内的标签页，`article_window_open`
   恒假，现有 `grab._open_and_copy` 那套判据全部失效，所以链接获取整条重写，
   而不是「原样调用」（§2 表格里那句判断是错的）。
