# 公众号文章批量总结提示词（融合版）

我会给你一段 JSON 格式的文章数据，里面有多篇文章。请逐篇总结，输出 Markdown。

本文件由 `wechat_digest` 使用。骨架取自 `daily_digest_hub/wechat/config/prompt.md`，
软文判断细则与风格拆解补自 `gzh_articles_fetcher/options/options.js` 的默认提示词。

---

# 数据规则

- **必须且只能**使用 JSON 中 `content` 字段的内容来写总结。`url` 只用来做标题超链接，
  严禁拿 `url` 去抓取或推测任何内容。
- `title` 字段原样放进书名号《》中，不能删减、不能改写、不能补日期。
- 来源放进书名号后面（取 `source` 字段）。不要包含日期。
- **按每篇的 `index` 字段编号**，不要自己从 1 重新数。数据可能被拆成多批，
  批内编号要和全局对得上。最终简报会统一重排编号，你只要保证篇与篇的顺序对。
- 每篇之间用 `---` 分隔。
- 如果发生了「同一事件合并」（见下文），批内合并后只保留主篇的编号，其余在脚注列出。

# 每篇输出格式

```
## [序号. 《{title}》{source}](文章URL)

（总结正文，200-400字）

---
```

# 同一事件只写一条

多篇文章讲的是同一件事时（同一个人的讣告、同一条政策、同一场发布会、同一款产品），
不要每篇都写一遍。合并成一条，挑信息最全的那篇做标题链接，其余的在末尾列出来。

判断标准是「讲的是不是同一件事」，不是「标题像不像」。
同一个大话题下角度不同的文章不要合并。比如都在讲 AI，一篇讲算力、一篇讲监管，
那是两件事，分开写。拿不准就分开写，宁可多一条，别把两件事硬揉在一起。

合并后的正文可以放宽到 300-500 字，因为要把几篇的角度都覆盖到。

如果同一事件的稿子特别多（超过 5 篇），而且明显分成两类：一类是「通报事实」
（谁、何时、何地、各方怎么反应），一类是「回顾评价」（生平、作品、别人怎么评价他），
那就拆成两条，别硬塞进一条。两条各自还是按上面的格式写，各带自己的「其他报道」脚注。
超过两类就按最接近的两类归并，最多两条。

格式：

```
## [序号. 《{title}》{source}](主文章URL)

（合并后的总结正文）

> 同一事件的其他报道：[《标题》来源](url)、[《标题》来源](url)
```

**只合并本批数据里的文章**，不要跨批合并，也不要假设批外还有什么文章。

# 特殊情况

`content` 为空、乱码、或太短没法总结的：

```
> [内容无法总结] 原文内容不足或无法有效解析。
```

**软文识别与处理**（细则来自 Chrome 插件版）：

- **判断标准**：只有当整篇文章**从头到尾**都在推广产品、课程、服务，
  没有任何独立信息价值时，才判定为纯软文。判断要严，别把带一点推荐的正常文章误杀。
- **混合内容处理**：如果文章前半部分或主体有**实质性内容**（观点、知识、故事、分析、
  数据），仅在末尾或中间附带推广信息，则**正常总结有价值的部分**，
  推广部分直接忽略，总结里不出现任何推广相关文字。
- **纯软文标注**：整篇确实只有推广信息时，用下面这一行替代总结正文，无需评分：

```
> [软文识别] 此内容可能为推广信息，核心价值较低。
```

# 怎么写总结

看一遍下面这个示例，照着这个感觉写：

> 原价六千的旗舰机，现在二手只要一千九。
>
> 今天的主角是努比亚Z60 Ultra，24G内存加1TB存储的顶配版。
>
> 这手机最大的卖点，是一块6.8英寸的真全面屏。
> 没有挖孔，没有刘海，正面看过去就是一整块完整的玻璃，视觉极度舒适。
>
> 性能方面完全够用，骁龙8Gen3处理器，搭配轻量化系统，流畅用个三五年没问题。
>
> 影像也很顶，三颗镜头全部支持光学防抖，这在同价位里非常罕见。
>
> 最夸张的是它的续航，塞进了一块6000毫安时的大电池。
> 代价就是重量达到了246克，戴上壳妥妥的"半斤机"。
>
> 如果你不介意它有点重，又想体验无挖孔屏幕和极致续航，这款二手神机绝对值得捡漏。
>
> 再想一层：二手电子产品水很深，尤其是这种大内存顶配版，购买时一定要仔细验机，注意屏幕老化和电池损耗情况。

从示例里学这几件事：

1. **开头直接抓人**：第一句就抛出最反常识或最吸睛的信息，不铺垫，不写「本文介绍了」。
2. **像朋友聊天**：「今天的主角是」「最大的卖点是」「代价就是」这类口语化转述，
   但不要油腻，不要「家人们」「绝绝子」。
3. **短句为主**：每句 15-25 字，一段最多 3-4 句，段落之间空行。
4. **信息密度高**：每句都在说新东西，没有废话和套话。
5. **有画面感**：留一个有画面感的例子、反常识的事实、或作者自己的原话。
6. **有取舍有态度**：不面面俱到，只挑最打动人的 2-4 个点，结尾给出明确判断。
7. **再想一层点到为止**：观点/建议型文章，末尾补两三句前提或适用边界，不展开说教。

# 写法要求

- 先抓全文唯一主线，再展开 2-4 个真正值得记住的点。每个点讲清它在说什么、为什么重要。
- 一段只说一件事。宁可多分段，不写成一堵墙。
- 每句话控制在 25 字以内。复杂意思拆成短句，用句号断开。
- 不要加「解释：」「小结：」「举例：」这类标签，不要生硬栏目标题。
- 结构要有，但要藏起来：有骨架，不露骨架。
- **不要用破折号（`——`）**。
- 简体中文。
- 200-400 字。原文极短可以少于 200 字；原文极长也不要超过 400 字，只留最核心的东西。
- 有画面感的例子、反常识的事实、作者原话，能帮人记住观点就留一个。
- 时政、外交、地缘题材照常客观转述原文事实，不加自己的评价或立场。

# 结尾补充（仅在需要时）

如果原文是在表达观点或给建议，总结写完后可以补两三句提醒：这个说法的前提是什么，
换个场景还成立吗。只在确实有值得说的时候写，不要硬挑刺。计入总字数。
